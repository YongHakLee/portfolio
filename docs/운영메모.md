# 운영 메모

이 저장소를 관리할 때 필요한 절차 모음. 사이트 방문자용 안내는 [README](../README.md)에 있다.

## 원본 이미지 가공

`images/`(프로필·프로젝트 원본)와 `projects/`(증빙 이미지 원본)는 저장소에 커밋하지 않는다.
웹용 사본만 `public/images/`에 커밋한다. 원본을 갱신했으면:

```bash
node scripts/prepare-assets.mjs
```

이 스크립트는 원본을 1600px 이내로 줄여 재압축하고(원본보다 커지면 원본을 그대로 쓴다),
유튜브 강의 썸네일 12장을 내려받는다.

`public/images/projects/3d-demo.png`만 예외다. 시연 영상에서 뽑은 포스터 컷인데
영상과 추출 스크립트를 함께 지웠으므로 재생성되지 않는다. 저장소의 파일이 원본이다.

`3d-eval.png`(시험성적서)는 가공할 때 두 곳을 흰 사각형으로 덮는다 — 우측 상단
G4B 진위확인코드와 좌측 하단 QR이다. 이 둘이면 누구나 정부 포털에서 원본 전문을
조회할 수 있는데, 포트폴리오가 근거로 삼는 것은 시험결과 항목이지 조회 경로가 아니다.
좌표는 `scripts/prepare-assets.mjs`의 `MASKS`에 이미지 크기 대비 비율로 들어 있다.
성적서 양식이 바뀌면 이 좌표부터 다시 맞춰야 한다.

## 배포

`main`에 push하면 GitHub Actions가 빌드 → 산출물 검사 → GitHub Pages 배포까지 자동으로 한다.
Actions 탭에서 수동 실행(`workflow_dispatch`)도 된다.

산출물 검사(`scripts/check-output.mjs`)는 네 페이지(`/`, `/resume`, `/work`, `/cv`)의
링크 개수·경로·앵커, 논문 13편 · 프로젝트 6건 같은 개수, 그리고
2026-08 정리에서 지운 흔적(`teamsparta`, `sparta`, `ai-engineering` 등)이
되돌아오지 않았는지 본다. 실패하면 배포가 멈춘다.
데이터(`src/data/`)에서 논문·프로젝트를 늘리거나 줄이면 이 스크립트의 기대 개수도 함께 고쳐야 한다.

이 저장소는 NFS 마운트 위에 있어 `.next`를 그대로 두면 `npm run build`가
`Error: Build directory is not writeable`로 막힌다(환경 문제이지 코드 문제가 아니다).
`.next`를 로컬 디스크로 심링크하면 빌드가 통과한다. 한 번만 해두면 된다:

```bash
mkdir -p ~/.cache/portfolio-build/next
ln -sfn "$PWD/node_modules" ~/.cache/portfolio-build/node_modules
rm -rf .next && ln -sfn ~/.cache/portfolio-build/next .next
```

`node_modules` 심링크를 빌드 디렉터리의 형제로 두는 것이 핵심이다. Turbopack이 청크
파일 경로에서 위로 올라가며 모듈을 찾으므로, 이게 없으면
`Cannot find module '@tailwindcss/postcss'`로 실패한다.

이렇게 하면 CI에서만 돌던 산출물 검사를 로컬에서도 돌릴 수 있다:

```bash
npm run lint
npx tsc --noEmit
npx next build && node scripts/check-output.mjs
npm run dev    # http://localhost:3000/portfolio
```

`npx tsc --noEmit`이 소스와 무관한 `TS1005: '?' expected`로 실패하면
dev 서버를 강제 종료해 `.next/dev/types/routes.d.ts`가 깨진 것이다.
`rm -rf .next/dev/types` 후 다시 돌린다.

## PDF로 저장하기

페이지 안에 인쇄 버튼은 두지 않는다. `/resume`, `/work`, `/cv`에서 `Ctrl/⌘ + P`:

- **대상** — PDF로 저장
- **여백** — 기본
- **배경 그래픽** — 켬

용지는 CSS가 A4 세로로 지정한다(`globals.css`의 `@media print`).
헤더·푸터, 인쇄 버튼, 페이지 안의 링크 안내는 `.no-print`로 인쇄에서 빠진다.

페이지 넘김 규칙은 `globals.css`의 `@media print`에 모여 있다. 이 블록은 레이어 밖이라
Tailwind 유틸리티(`@layer utilities`)를 덮어쓴다 — `mt-20` 같은 클래스도 여기서 조정된다.

- `.print-avoid-break`는 **섹션이 아니라 항목에** 붙인다. 섹션 전체를 묶으면 학력·논문
  목록처럼 긴 블록이 통째로 다음 장으로 밀려 앞 쪽에 큰 여백이 생긴다.
- `li`, `img`는 전역으로 `break-inside: avoid`, `h1~h4`는 `break-after: avoid`라
  제목만 페이지 끝에 남지 않는다. `p`, `li`의 `orphans/widows: 3`이 한 줄 낙오를 막는다.
- 프로젝트 이미지는 인쇄에서 `max-height: 88mm`로 묶는다. 원본 비율 그대로면 이미지 한 행이
  A4 한 쪽을 거의 채워, 남은 자리에 못 들어가고 통째로 다음 장으로 밀린다(앞 쪽 40% 공백).

레이아웃을 건드렸으면 실제로 PDF를 뽑아 쪽마다 하단 여백을 확인한다.
마지막 쪽을 빼고 하단 여백이 25%를 넘으면 어딘가에서 덩어리가 통째로 밀린 것이다:

```bash
pdftotext -bbox 저장한.pdf - | python3 -c '
import re, sys
for i, (h, body) in enumerate(re.findall(r"<page width=\"[\d.]+\" height=\"([\d.]+)\">(.*?)</page>", sys.stdin.read(), re.S), 1):
    ys = [float(y) for y in re.findall(r"yMax=\"([\d.]+)\"", body)]
    if ys: print(f"p{i}: 하단 여백 {(float(h) - max(ys)) / float(h) * 100:5.1f}%")'
```

이미지가 페이지 끝에 오는 쪽은 이 수치가 실제보다 크게 나온다(텍스트만 재기 때문).
그럴 때는 `pdftoppm -png -r 55 저장한.pdf 쪽`으로 뽑아 눈으로 본다.

기준(2026-08): 이력서 3쪽, CV 3쪽, 포트폴리오 8쪽.

## 영문 CV

`/cv`는 `cv/cv.pdf`(LaTeX 원본, 저장소에는 커밋하지 않는다)와 같은 내용을 HTML로 옮긴 것이다.
논문·특허·국가 R&D는 `src/data/research.ts` 한 곳을 이력서·포트폴리오와 함께 쓰고,
영문 CV에만 있는 항목(Education, Experiences, Technical Skills, References)만
`src/data/cv.ts`에 있다. `cv.tex`를 고쳤으면 이 두 파일도 같이 맞춘다.

원본 PDF에 있는 휴대전화 번호와 지도교수 사무실 전화는 공개 페이지에 싣지 않는다.
`check-output.mjs`의 "전화번호 미노출" 검사가 이걸 지킨다.
